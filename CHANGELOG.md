## [Unreleased]

### Added
- App icon: `App/Assets.xcassets/AppIcon.appiconset` (lime "R" + claw slashes on near-black, 1024 master + all 10 required macOS sizes) wired into `Raptor.xcodeproj` (`ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon` in Debug and Release). The project previously had no icon asset at all, so even a successful first Xcode build would have shown the generic macOS icon. `scripts/check.sh` now verifies the catalog, the 1024 master and the project wiring. Revised 2026-11-26 with an Xbox vibe: glossy Xbox-green orb behind the R and a bold white X in the top-right corner (replacing the claw slashes); regenerated by `scripts/make-appicon.py`. Not yet compiled in Xcode — first build still needs a Mac.
- Xcode project file `Raptor.xcodeproj` (macOS 13+, Swift 5, bundle id `dev.raptor.rebuild`, shared `Raptor` scheme): open it and press Cmd+R instead of creating a project by hand. All 15 Swift files under `App/` are in the Sources phase and the 3 sample `.lua` files are in Resources; Info.plist is generated by Xcode, App Sandbox is off, hardened runtime on. NOT yet compiled in Xcode (no macOS/Xcode on the build machine) — first-build errors, if any, still need fixing on a Mac.
- One-liner Mac install: `installer/bootstrap.sh` — clones the public repo into `~/raptor-rebuild` and runs the safe installer. Usable as `cd ~/ && curl -fsSL https://raw.githubusercontent.com/Cherryo0/raptor-rebuild/v1.1.0/installer/bootstrap.sh -o /tmp/raptor-bootstrap.sh && bash /tmp/raptor-bootstrap.sh`, with `--dry-run` / `--force` / `--dir` / `--ref` options. Documented in `installer/README.md` and `docs/modules/02-installer.md`.

### Fixed
- `installer/bootstrap.sh`: removed all bash array use — expanding an empty array under `set -u` aborts on macOS's stock bash 3.2 with `args[@]: unbound variable` (line 104), while newer bash tolerates it, so Linux tests had passed. Flags are now passed with explicit branches; the script is written for bash 3.2 throughout.
- Install one-liner: replaced `curl ... | bash </dev/tty` with download-then-run — the pipe form runs on macOS (zsh) but leaves bash waiting for terminal input after the script finishes, so the terminal looks stuck. If that happened, press Ctrl-C once — the install already finished.
- `installer/quickfix.sh`: create `~/Downloads` before rewriting `raptor-version.json` (same fresh-HOME bug as `install.sh`).
- `scripts/check.sh`: now syntax-checks `installer/bootstrap.sh` too.
- Initial clean-room rebuild: SwiftUI macOS app skeleton (editor, tabs, hub, settings, licensing).
- Safe installer rewrite (`installer/install.sh`) and repair script (`installer/quickfix.sh`) — launcher placeholder + UI scripts dir only.
- Python API client prototype (`api-client/`) with mocked pytest suite.
- Research docs: raptor.fun findings, install.sh analysis (v4.1, SHA256 ebb3abbf…), reverse-skill methodology, malware trust check.
- 18 per-module docs under `docs/modules/`, plus `docs/ROADMAP.md` and `docs/DECISIONS.md`.
- Root `ARCHITECTURE.md`, `CONTRIBUTING.md`, `SECURITY.md`, MIT `LICENSE`.

### Security
- Injection bridge is a stub only (`.notImplemented`); no dylib injection, codesign stripping, HWID spoofing, or Luau execution against Roblox.
- Installer: HTTPS only, `--dry-run`, backup before replace, confirmation before deletes, no secrets in URLs.

## [1.1.0] — 2026-10-25
- One-liner install is now pinned to this tag in the README/installer docs, after GitHub's raw-file cache served the pre-fix bootstrap for minutes after the fix was pushed.
- Bootstrap fix (see Unreleased → Fixed): no arrays, bash 3.2 safe.
- Install command changed to download-then-run (`curl ... -o /tmp/raptor-bootstrap.sh && bash /tmp/raptor-bootstrap.sh`): the `curl ... | bash </dev/tty` form runs on macOS (zsh) but leaves bash waiting for terminal input after the script finishes, so the terminal looks stuck. Verified with pty tests: pipe form hangs, download form exits 0.
